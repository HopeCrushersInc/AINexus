# Current project status

Release: **0.2.0-preview.16**, Windows x64 development preview, 2026-10-29. This adds explicit read-only 7z archive inspection after user-selected tool/archive review. Parsing runs in the portal's own resource-limited worker; it extracts, installs and launches no archive payload. Previous neutral tool selection and no-preinstalled-AI policy remain in place.

## Working within tested limits

- Explicit 7z metadata inspection for the selected archive: verify exact size/SHA-256, list declared expanded sizes and possible license filenames, and reject unsafe metadata. A Windows job limits the owned worker to 768 MiB and one process, with a ten-minute parent deadline and bounded input/output. This is resource isolation, not a general OS security sandbox. Payload decompression, dependency terms, installation and execution remain unverified.
- Official ComfyUI archive acquisition: **Find image tools → select the official ComfyUI result → Review archive download**, check releases, select an archive, choose an existing folder, review exact source/bytes/hash/terms/destination, approve, then download. Files are SHA-256 verified; conflicts preserved and owned partials cleaned. Receipts explicitly record no extraction, installation or execution. Source names do not prove GPU/driver compatibility.
- Simpler task/action buttons and a static black-hole backdrop. Standard starts each session; choose among ten visible styles (Standard, LCARS, Cyberpunk, Midnight, Ocean, Forest, Ember, Graphite, Paper, Terminal). Paper and Graphite use quiet plain backgrounds; Terminal uses a static grid. Shift-clicking LCARS still opens hidden Retro. Shift-wheel or the Size menu scales text/buttons from 75% to 175%, with reset to 100%. Native title-bar dragging and all-edge/corner resizing remain available.
- Actual CPU, RAM, GPU/driver and fixed-volume scans. Workload choices start unchecked and are not remembered.
- Confirmed workloads initiate source searches. GGUF text-model artifacts have source links, pinned revisions, available sizes/hashes/licenses and local resource estimates. User selection is required; no model is selected automatically.
- Text discovery combines popular, trending and recently updated text-generation GGUF feeds. Broad searches interleave and deduplicate repository IDs, inspect at most 24 repositories with four concurrent reads and return up to 48 results including supporting runtime metadata. Users can choose a single source order or explicitly browse an exact repository's standalone files. Failed feeds retain successful results; coverage is bounded.
- All returned models, tools and runtimes remain visible by default even when requirements are unknown or unmet. The optional unchecked **Show only estimated-fit results** filter narrows the list. **Available action** distinguishes file download, manual tool setup and video-pipeline inspection. Selected-drive storage, conservative runtime-memory estimates and the actual shortage reason are separate. Equal-assessment results preserve source order rather than favoring smaller models. Available RAM can qualify a CPU path when full GPU offload does not fit; partial offload remains unassessed.
- Source-reported repository parameters, modification dates and downloads are shown where available. Missing facts remain unknown. Those values do not establish an exact file's architecture, release date, quality or speed. Known non-text tasks and named projectors, importance matrices, drafts and adapters are excluded from primary text-model results.
- Explicit benchmark-evidence lookup for an exact repository: opening copies the selected source without an HTTP request; a separate action reads reported benchmark/task values, dates, source attribution, nullable source-verification flags and PR numbers. When a catalog is configured, bounded source snapshots are saved privately beside it. **Load saved evidence** makes no online request or fallback, displays the original retrieval time and identifies potentially stale saved facts. Save failures preserve usable live evidence with a warning; corrupt saved files are preserved and reported. Parsing is limited to 32 inspected rows and carries no evaluated-weights or quantization-equivalence claim. Changing the model or repository cancels stale displays. Missing scores stay unknown; upstream scores are not substituted and attribution links are not fetched. Model choices and approvals are not saved.
- Image discovery retrieves bounded public text-to-image Safetensors artifact metadata and separate tool repositories. Exact repository queries inspect that source directly. Pinned identity and available bytes/hashes/licenses are preserved; missing facts stay unknown. Candidates are visible as unverified, with no fabricated hardware-fit or complete-checkpoint claim.
- Exact image-artifact data acquisition: select a result marked **Review image file download**, open its review, choose an existing folder, review fresh source/storage evidence, approve its precise plan, then download/verify bytes and SHA-256 and save a separate private image receipt. Matching existing files are rehashed for reuse; conflicts are preserved. **Choose tool / connect folder** first requires an explicit engine choice, then a supported adapter may open its separate configuration review. Generator applications marked **View source / manual setup** have no integrated installer; their review keeps source details visible, and the source page opens only on an explicit click. No engine is configured or launched by file acquisition.
- Video discovery now searches public text-to-video and image-to-video Hugging Face feeds and video tools. Two feeds contribute up to four repositories each; up to eight unique repositories are inspected, with at most eleven metadata requests. Exact repository queries inspect only that source. Candidates retain pinned public repository/model-card identities, tasks and available licensing/signals without inventing a complete model-file inventory or download size. Video pipeline review stays in Discover and declares missing runtime/install/hardware evidence; it does not start an image/text setup flow or download weights.
- Separate approved checkpoint-folder connections for an existing portable ComfyUI engine. Review exact folders, config contents/hash and backup, then explicitly apply. Only the dedicated JSON and recoverable backup are written; original YAML is preserved. Changed or stale inputs revoke approval. The installed folder mapping is read on a later explicit engine start, without remembering workload/model selections or approvals.
- Supported GGUF acquisition: exact-plan approval, bounded transfer, byte/SHA-256 verification, matching existing-file reuse, receipts and no overwrite of a different file.
- Existing llama.cpp configuration, model loading, smoke generation and local multi-turn chat. The runtime runs with its offline-mode flag; OS-enforced network isolation is not claimed.
- New native CPU-runtime ZIP review/download/inspection/extraction with separate approvals. Existing approved GPU-capable runtimes can be selected; automatic GPU runtime/dependency setup remains incomplete.
- Persistent SQLite source catalog and offline Library filtering. Private tracked-folder receipt links report missing files, size mismatches and source conflicts; a historical receipt is not current integrity or runtime proof.
- Supported GGUF models can be chosen in Library with an explicit installed-copy selection and local source/path review, followed by explicit loading with an existing engine. Review starts no search, download or engine. Loading binds the receipt to that exact plan/artifact/path, verifies the current hash, checks current hardware capacity and tests generation; the model is protected against writes during those steps.
- Explicit local integrity checks and read-only recovery reviews. Recovery review does not perform repair.
- Optional per-card NVIDIA power inspection and user-approved changes within reported bounds. No fixed wattage, automatic restoration or power-control launch requirement.
- Connection to an existing ComfyUI engine/checkpoint and standard image generation. Actual SD1.5 and SDXL Base generation has been validated for the specific tested PC/runtime/checkpoint combinations, using explicit checkpoint choices and both folder configurations.
- Session-only image width/height inputs from 256 to 1024 pixels, in multiples of 64. Invalid inputs stop before resource admission or HTTP. The actual workflow payload carries the explicitly requested dimensions and checkpoint; no checkpoint is chosen automatically.

## Partial, unfinished or unverified

- Image-file acquisition and the narrow existing-engine folder connection are supported. Complete checkpoint/companion-asset proof, general generator-engine/dependency installation and evidence-backed media hardware requirements remain unfinished. A downloaded file may be an adapter or component. Video choices are pinned repository-level metadata: complete file inventories, companion assets, compatible runtime setup, video download/install and actual generation remain unimplemented. Music and other non-text categories still search tool repositories. Manual source browsing is available, not an automatic installer.
- No general multi-item installation queue, automatic text/image server switching or model updates/repair/rollback. The installed-Library flow covers supported GGUF text models and existing engines; other model/tool launch adapters remain incomplete.
- Actual image validation covers SD1.5 at 512×512 and SDXL Base at 1024×1024; earlier SD1.5 1024×768 evidence is retained. Other architectures, resolutions and PC/runtime combinations remain unverified. Size bounds do not establish that every checkpoint supports every size or fits available memory.
- Four-GPU identity/control fixtures pass, but actual four-GPU execution and arbitrary model splitting are unverified. Available VRAM is not silently pooled. Scaling beyond the immediate 1–4 local GPU scope is deferred.
- No implemented automatic fan control, thermal shutdown policy, training pipeline, persistent worker services or finished dockable/popout workflows.
- Linux, macOS and ARM64 portal releases remain planned. Current packages are Windows x64 only.
- iCUE investigation has installer inventory evidence, not a rebuilt/custom iCUE package. Ghidra-based analysis and feature transplantation remain unfinished.
- Coding/agent category labels are search scope, not proof of capability or quality. Source metadata is publisher-supplied; missing requirements remain unknown.
- No universal best-model score, independent Nexus task evaluation, comparable benchmark ranking or normalized benchmark-evidence catalog. Private raw evaluation snapshots can be reopened offline, but that does not establish freshness or independent verification. Reported source verification is not verification by Nexus, and a PR number does not establish acceptance. Source pagination and complete split-GGUF inventory support remain unfinished.
